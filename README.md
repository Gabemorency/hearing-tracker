# hearing-tracker

A live tracker for U.S. Senate and House committee hearings, plus a directory of
current members of Congress. Served as a static site via GitHub Pages — there is
no application server; all data is produced by scheduled GitHub Actions that
scrape public sources and commit the results straight to `main`.

## Site

- `index.html` — today's hearings across House and Senate committees, refreshed every 2 hours.
- `calendar.html` — upcoming hearing schedule.
- `members.html` / `bios/*.html` — member directory with per-member bio pages.
- `manifest.json`, `sw.js`, `offline.html` — PWA/offline support.

## Data pipeline (GitHub Actions)

| Workflow | Schedule | What it does |
|---|---|---|
| `update.yml` | every 2 hours | Runs `scrape.py` (Playwright) against committee pages, merges into `snapshot.json`, pulls DomeWatch floor data, rebuilds `index.html`. |
| `nightly.yml` | weeknights, 9pm ET | Runs `build_baseline.py` (tomorrow's schedule) and `build_members.py` (full member directory + bio pages), rebuilds `calendar.html`/`members.html`. |
| `bio_sync.yml` | every 6 hours | Detects new/departed members against `unitedstates/congress-legislators`, uses the Claude API to write bios for new members, updates `bios_hardcoded.json`. |
| `generate_bios.yml` | manual only | One-time/bulk regeneration of all member bios via Claude. |
| `validate.yml` | every 3 days | Sanity-checks hardcoded data (institutional leadership, CBC roster, vacant seats) against live sources; opens a GitHub issue on drift. |
| `tests.yml` | every push/PR | Runs the pytest smoke tests in `tests/`. |

`scrape.py` and `build_baseline.py` scrape committee pages directly (Playwright +
BeautifulSoup/pdfplumber for witness-list PDFs). `build_members.py` and
`bio_sync.py`/`generate_bios.py` pull structured data from the
[unitedstates/congress-legislators](https://github.com/unitedstates/congress-legislators)
project rather than scraping.

`baseline.json` is the source of truth for "what hearings are scheduled" —
`scrape.py` only enriches it (room changes, witness lists, cancellations) and
never overwrites baseline entries wholesale, so a bad scrape can't silently
delete a real hearing.

## Data files

- `bios_hardcoded.json` — member bio text, keyed by bioguide ID. Written by
  `bio_sync.py`/`generate_bios.py`, read by `build_members.py`. Plain JSON
  (not committed as Python source) so diffs stay readable and the file has no
  import-time side effects.
- `members.json` / `baseline.json` / `domewatch_*.json` — generated data,
  regenerated by their respective workflows. Don't hand-edit; changes will be
  overwritten on the next run.

## Secrets

Two API keys are used, both as GitHub Actions secrets:

- `CONGRESS_API_KEY` — congress.gov API.
- `DOMEWATCH_API_KEY` — DomeWatch live floor data API.
- `ANTHROPIC_API_KEY` — Claude API, used only server-side in `bio_sync.py`/`generate_bios.py`.

Because this site has no backend, any key embedded in client-side JS
(`domewatch.js`, the congress.gov snippet in bio pages) is visible to anyone
who views source — `inject_keys.py` intentionally leaves these as
`__DOMEWATCH_KEY__`/`__CONGRESS_KEY__` placeholders in committed files so a
real key is never checked into the public repo. Those two client-side
integrations only become fully live if a server-side proxy is added to hold
the real key; until then they degrade gracefully (no key → feature no-ops).

## Tests

`tests/` has pytest smoke tests for the pure parsing/formatting helpers in
`scrape.py` and `build_members.py` (committee-name normalization, hearing
matching/diffing, witness extraction, member formatting). They don't hit the
network. Run locally with:

```
pip install pytest playwright beautifulsoup4 lxml pdfplumber requests pyyaml
python -m pytest tests/ -v
```
